Fetch numerical observations and source metadata for statistical variables from `search_indicators` on entities from `resolve_entities`.

- **Batching:** pass related variables that share `observation_properties` and all target entities in one call (or parallel calls when above the per-call limits) instead of calling once per entity or variable. Standard single-entity variables (empty `observation_properties` in `search_indicators`; topic `member_variables` omit `observation_properties` and are typically single-entity) use `observationAbout` and can be batched together.
- **Child entities:** for all entities of a type inside a place (e.g. counties of California, schools in a district), pass only the parent place in `entity_dcids` and set `child_entity_type_dcid`; do not resolve or list individual child entities.
- **Multi-entity variables:** when a variable's `observation_properties` in `search_indicators` is non-empty (e.g. `["donor", "recipient"]` or `["observationAbout", "sourceCounty"]`), set `entity_property` to the role constrained by `entity_dcids` (or `child_entity_type_dcid`) and pass any other constrained roles in `additional_entities`. Omit a counterpart role from `additional_entities` to fetch observations across all counterparts.
- **Dates and sources:** primary source selection already considers all available sources within the requested date window. Avoid `date='all'` on daily or monthly series (`observation_period` `P1D` or `P1M`) and pass a bounded `date_range_start` and `date_range_end` instead. When comparing entities or variables, check whether returned dates align and fetch a shared date or range if needed. Pass `source_override` only to pin a specific source (for example to align units, measurement methods, or entity coverage); to compare which years or entities each source covers, call `get_variable_metadata` once rather than trying sources one call at a time.

`entity_metadata` maps every entity DCID appearing in the returned rows to its display name once across the response. `observations` lists one entry per requested variable in request order: `data` holds columns `["observationAbout", "date", "value"]` (or `[<observation_properties...>, "date", "value"]` for multi-entity variables), `source_metadata` identifies the selected source (`source_id`, `import_name`, `provenance_url`, `unit`, `scaling_factor`, `measurement_method`, `observation_period`), `alternative_sources` lists other available sources in rank order (with `entities_found_count` when the primary source covers more than one entity or entity combination), and `note` explains when a variable has no observations for the requested entities or date window. `scaling_factor` is the denominator of a rate or percentage (for example, `value` `28.4` with `scaling_factor` `"100"` means `28.4` per `100`, or `28.4%`; `scaling_factor` `"1000"` means per `1,000`).
